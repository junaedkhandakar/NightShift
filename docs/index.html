Unattended Execution Safety

Why NightShift makes unattended work safe

01

Fresh Process per Task

AI agents running in single long sessions suffer severe context rot and exponentially growing token costs. NightShift spawns a completely fresh sub-process for every task.

No 8-hour context decay • Strict turn caps
02

External Test Gate

The agent self-reporting "I finished the task!" counts for nothing. NightShift runs your real test gate (npm test, cargo test). If tests fail, the code is rejected.

Exit 0 required • Protected path guards
03

Ephemeral Git Worktrees

Every task is given an isolated worktree under .nightshift/work/<id>. One bad task cannot poison the next, and nothing is ever merged into main automatically.

Clean reviewable branches • Zero main tree pollution

Execution Pipeline

How a task travels through NightShift

1
Atomic Queue Lock
tasks/queue/01-auth.md is atomically moved to tasks/queue/.running/ so multiple runners or crashes cannot process duplicate tasks.
2
Clean Worktree Provisioning
Cuts a fresh git worktree at .nightshift/work/01-auth on branch nightshift/01-auth pinned to the base commit.
3
Agent Invocation via Pointer
Instructions write to .nightshift/prompt.md. Agent runs non-interactively. Output streams directly to .nightshift/logs/01-auth.jsonl.
4
Protected Path Audit & Test Gate
NightShift checks if the agent touched test definitions or CI locks. If clean, it runs gate: ["npm test"].
Pass: Commit & Report

Commits branch nightshift/01-auth, moves to tasks/done/, and appends diffstat to .nightshift/REPORT.md.

Fail: Quarantine & BLOCKED.md

Reverts changes, moves task to tasks/failed/, logs failure reason, and captures agent blocker report.

Quick Start Guide

From zero to overnight running in 5 minutes

Step 1 Scaffold your repo

Run inside your project's root git repository to generate the configuration and task queue folders.

nightshift init
Step 2 Verify environment with doctor

Diagnoses Node.js version, Git repository status, and confirms your AI agent CLI is available in PATH.

nightshift doctor
Step 3 Set up your Test Gate

Open nightshift.config.json and define the check commands that the agent's work must pass.

{
  "harness": "claude",
  "gate": ["npm test", "npm run build"],
  "protect": ["tests/**", "*.test.*", ".github/**", "package-lock.json"]
}
Step 4 Write a task in tasks/queue/

Create tasks/queue/001-fix-auth.md with clear acceptance criteria:

---
minutes: 20
turns: 30
gate: npm test -- tests/auth
---

# Fix Expired Session Redirect
When the auth token expires, redirect `/dashboard` to `/login?expired=true`.
Do not modify any test definitions or add dependencies.
Step 5 Test Free (Dry Run) & Start Overnight

Run a simulated pass for free, then launch the real unattended run:

# 1. Test plumbing with fake agent (zero API cost)
nightshift run --dry-run --once

# 2. Run the overnight queue for real
nightshift run

FAQ & Troubleshooting

        
Frequently Asked Questions

      


      

        
        

          
            What happens if the agent fails or enters an infinite loop?
            ↓
          
          

            NightShift enforces strict process-tree wall-clock timeouts via limits.minutes (default 45 mins). If a task exceeds its allotted minutes or conversational turns, NightShift terminates the process tree, records the timeout in REPORT.md, moves the task to tasks/failed/, and safely moves to the next task.
          

        


        

          
            Does NightShift push directly or merge into my main branch?
            ↓
          
          

            Never. NightShift never pushes to remote or merges into main automatically. Every successful task produces its own isolated git branch (nightshift/<task-id>). You inspect the branch and diff in the morning and merge only what you trust.
          

        


        

          
            What are protected paths?
            ↓
          
          

            By default, tests/**, *.test.*, .github/**, and package-lock.json are protected. If a lazy agent attempts to pass a test gate by deleting test assertions or commenting out tests, NightShift detects the modification, rejects the task immediately, and quarantines it.
          

        


        

          
            Where should I run NightShift overnight?
            ↓
          
          

            Since laptops sleep when the lid is closed, run NightShift on an always-on home server, a secondary mini-PC, a cloud VPS inside tmux (tmux new -s night), or via GitHub Actions (see templates/github-action.yml).
